# OrangeHRM Automation Assessment

## Overview

This project contains UI automation tests for the OrangeHRM application using:

- Java
- Selenium WebDriver
- TestNG
- Maven
- Page Object Model (POM)

Application under test:

https://opensource-demo.orangehrmlive.com/

Test Coverage

The automation covers the following employee management scenarios:

Login
Verify login page elements
Login with valid credentials
Verify dashboard is displayed
Verify logged-in user information
Add Employee
Create a new employee using unique test data
Verify employee details page
Verify generated Employee ID
Verify created employee appears in the employee list
Search Employee
Search for the created employee
Verify employee details
Verify Employee ID
Verify employee name and last name
Update Employee
Update employee first name
Verify updated employee information
Delete Employee
Search for the updated employee
Delete the employee
Confirm deletion
Verify successful deletion message
Verify employee is no longer displayed
Test Data

Test data is generated dynamically to avoid duplicate employee records.

The Employee ID is generated by the application and retrieved from the Employee ID field after saving the employee.

Configuration

Configuration values such as:

Application URL
Username
Password
Employee search data

are stored in the project configuration rather than being hard-coded throughout the tests.

Running the Tests

Run all tests:

mvn clean test

Run smoke tests:

mvn clean test -Dgroups=smoke

Run regression tests:

mvn clean test -Dgroups=regression
Test Groups

Tests are organized using TestNG groups.

Example:

@Test(groups = {"smoke", "regression"})
Smoke

Contains the critical functionality required to verify that the application is working.

Regression

Contains the broader employee management test coverage.

Design Approach

The framework follows the Page Object Model pattern.

Page Objects

Page-specific locators and actions are maintained inside page classes.

Examples:

LoginPage
DashboardPage
AddEmployeePage
EmployeeSearchPage
Tests

Test classes contain the business flow and assertions rather than locator implementation.

Assertions

Assertions verify:

Page availability
Employee creation
Employee ID generation
Employee search results
Employee information
Employee update
Employee deletion
Success messages
Browser

The tests currently execute using Google Chrome and Selenium WebDriver.

Notes

The framework uses explicit waits to synchronize Selenium interactions with the application.

Unique employee data is generated during execution to reduce test-data collisions.

## Known Defect

### Leave Balance Deduction Is Incorrect

**Title:** Leave Balance Deducts 4 Days Instead of 3 for a 10–12 August Leave Request

**Steps to Reproduce:**

1. Login as an employee.
2. Open the Leave Request page.
3. Select a valid Leave Type.
4. Select From Date: 10 August.

7. Check the employee leave balance.

**Expected Result:**

The system should deduct 3 leave days from the employee's leave balance.

**Actual Result:**

The system displays 3 leave days but deducts 4 days from the employee's leave balance.
